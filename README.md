# Larix Addon Manager

Desktop-приложение на Python/PySide6 для подготовки и управления конфигурациями Larix.

Текущая версия приложения работает **только как Manager**. Viewer и BIM Sync в текущую сборку не входят.

## Возможности

- **Адаптеры** — настройка сопоставления параметров и формирование XML-адаптеров.
- **Наборы** — создание наборов/профилей Larix из одного Excel-файла; можно выбирать несколько листов и объединять их или создавать отдельные профили.
- **Матрицы** — подготовка профилей коллизий из одного Excel-файла; можно отметить несколько матричных листов, а фильтры брать из листа наборов того же файла.
- **Параметры** — создание и проверка профилей параметров, мультивыбор листов, объединение нескольких листов в один профиль или создание отдельных профилей, выбор параметров фильтрации из API или Excel-адаптера.
- **Excel-шаблон** — единая демонстрационная книга, на которой новый пользователь может сразу проверить Адаптеры, Наборы, Матрицы и Параметры и увидеть, как они связаны между собой.
- **Import XML** — отдельный инструмент для загрузки изменений из XML/Excel.
- Светлая и тёмная темы интерфейса.
- Настраиваемый адрес Larix API; по умолчанию используется `http://localhost:5000`.


## Общий Excel-шаблон

Ссылка **«Скачать шаблон Excel»** в главном окне создаёт книгу с готовыми примерами:

- `Инструкция` — кратко объясняет назначение остальных листов;
- `Набор 1` и `Набор 2` — расширенные примеры с несколькими разделами, большим количеством строк и LOI-параметров. Их можно использовать и в **Наборах**, и в **Параметрах**;
- `Наборы матрицы` — значения наборов для фильтров матриц;
- `Матрица 1` и `Матрица 2` — крупные примеры матриц на несколько дисциплин с допусками `A/B/C` и проверкой дублирования `D`;
- `Адаптер` — расширенный пример с группами `IBIM`, `Классификатор`, `BIM` и `Larix` для проверки импорта и выбора параметров через **«Из адаптера»**.

В **Наборах** и **Параметрах** можно отметить `Набор 1` и `Набор 2` одновременно. Галочка **«Объединить листы в один профиль»** определяет, будет один общий профиль или отдельный профиль на каждый лист.

В **Матрицах** Excel выбирается только один раз. После этого можно отметить `Матрица 1` и `Матрица 2`, а `Наборы матрицы` выбрать как источник значений для фильтров. Для нескольких матричных листов приложение создаёт один `.cv`, внутри которого находится отдельный профиль для каждого выбранного листа.

## Работа с Larix API

Приложение рассчитано на актуальную схему локального `EST.WebApi`.

При подключении приложение:

1. проверяет доступность API через `GET /getApiVersion`;
2. выполняет авторизацию через `POST /auth`;
3. получает `accessToken` и `refreshToken`;
4. отправляет защищённые запросы с `Authorization: Bearer <accessToken>`;
5. при истечении токена пытается обновить его через `POST /refresh`, а при необходимости выполняет повторную авторизацию.

Адрес API можно изменить в главном окне или задать через переменную окружения:

```text
LARIX_API_BASE_URL=http://localhost:5000
```

## Требования

- Windows.
- Python 3.
- Запущенный локальный Larix `EST.WebApi` для функций, работающих с API.
- Python-пакеты из `requirements.txt`.

## Установка для разработки

```bat
py -3 -m venv .venv
.venv\Scripts\activate
py -3 -m pip install --upgrade pip
py -3 -m pip install -r requirements.txt
```

## Запуск

Единственная точка входа:

```bat
py -3 main.py
```

## Сборка EXE

Для сборки основной версии используется:

```bat
build_main.bat
```

Результат:

```text
dist\Larix_Main.exe
```

Сборка содержит только Manager-модули и необходимые им ресурсы.

## Что не должно попадать в Git

Корневой `.gitignore` исключает:

- `build/`, `dist/`, `*.spec`;
- `__pycache__/`, `*.pyc` и кэши инструментов;
- виртуальные окружения;
- логи и HAR-файлы;
- локальные БД и пользовательские выгрузки;
- временные и резервные файлы;
- `.env` и локальные настройки IDE/ОС;
- рабочие файлы, создаваемые инструментами `importxml`.

Подробная схема модулей и связей находится в [`docs/project-architecture.md`](docs/project-architecture.md).
