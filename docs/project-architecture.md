# Project Architecture

## 1. Назначение

Larix Addon Manager — desktop-приложение на Python/PySide6 для подготовки конфигураций Larix. Основное приложение содержит четыре раздела: **Адаптеры**, **Наборы**, **Матрицы** и **Параметры**. Дополнительно в репозитории находится самостоятельный инструмент `importxml` для загрузки изменений из XML/Excel.

Основной стек: `PySide6`, `pandas`, `requests`, `openpyxl`, `PyInstaller`.

## 2. Точки входа

| Путь | Назначение |
|---|---|
| `main.py` | Единственная точка входа. Создаёт `AppMainWindow` из `shared/app_common.py` и подключает Manager-модули. |
| `importxml/XML.py` | Самостоятельный инструмент импорта XML/Excel в Larix API. |
| `build_main.bat` | PyInstaller-сборка `dist/Larix_Main.exe`. |

Основной запуск:

```bat
py -3 main.py
```

Сборка:

```bat
build_main.bat
```

## 3. Структура

| Путь | Роль |
|---|---|
| `main.py` | Единственная точка входа приложения и конфигурация доступных разделов. |
| `Adapters/ui.py` | UI редактора адаптеров, API-запросы и XML-сериализация. |
| `Sets/ui.py` | Наборы/профили Larix, импорт Excel/API и генерация XML-структур. |
| `Matrix/ui.py` | Матрицы и профили коллизий. |
| `Validator/ui.py` | Основной UI генерации профилей параметров. |
| `shared/app_common.py` | Основная оболочка Manager: главное окно, навигация, API-проверка, тема и загрузка модулей. |
| `shared/theme_toggle.py` | Тема, иконки, кнопка возврата и общие UI-помощники. |
| `shared/dialogs.py` | Унифицированные диалоги. |
| `shared/excel_parser.py` | Разбор структуры Excel-листов. |
| `shared/excel_template.py` | Генерация общего Excel-шаблона. |
| `shared/adapter_excel.py` | Чтение параметров из Excel-адаптеров. |
| `shared/guide.py` | Встроенные мини-гайды основных разделов. |
| `shared/adapter_picker.py` | Общий диалог выбора параметра из адаптера. |

## 4. Архитектурные слои

```text
UI / Desktop
  ↓
Application / Navigation
  ↓
Transformation Logic
  ↓
Larix API / Files
```

### UI / Desktop

`main.py`, `shared/app_common.py`, `Adapters/ui.py`, `Sets/ui.py`, `Matrix/ui.py`, `Validator/ui.py`.

Эти файлы отвечают за окна, диалоги, пользовательский ввод, карточки разделов и запуск операций.

### Application / Navigation

`main.py` задаёт список доступных разделов, а `shared/app_common.py` динамически загружает рабочие модули через `importlib` и встраивает их `centralWidget` в основное окно.

### Transformation Logic

`Adapters/ui.py`, `Sets/ui.py`, `Matrix/ui.py`, `Validator/ui.py`, `shared/excel_parser.py`, `shared/excel_template.py`, `shared/adapter_excel.py`, `shared/adapter_picker.py`, `importxml/XML.py`.

Здесь находятся разбор Excel/XML, формирование адаптеров, наборов, матриц и профилей параметров.

### Integrations

HTTP-вызовы Larix API выполняются через единый клиент `shared/larix_api.py`, который отвечает за авторизацию, токены и повторные запросы. Адрес API передаётся через переменную окружения `LARIX_API_BASE_URL`; значение по умолчанию — `http://localhost:5000`.

## 5. Основные сценарии

### 5.1 Главное приложение

```text
main.py
  ├─ Adapters/ui.py
  ├─ Sets/ui.py
  ├─ Matrix/ui.py
  └─ Validator/ui.py
```

`main.py` задаёт четыре карточки разделов, а `shared/app_common.py` отображает их и загружает выбранный UI-модуль динамически.

### 5.2 Адаптеры

```text
main.py → Adapters/ui.py → Larix API / XML
```

Модуль получает доступные данные из API, позволяет настроить сопоставление и формирует XML-адаптер.

### 5.3 Наборы, матрицы и параметры

```text
main.py
  ├─ Sets/ui.py
  ├─ Matrix/ui.py
  └─ Validator/ui.py
       ↓
shared/excel_parser.py / shared/excel_template.py
```

Модули читают Excel/API-данные и формируют соответствующие конфигурации Larix.

### 5.4 Import XML

```text
importxml/XML.py → Larix API
```

Самостоятельный инструмент читает XML/Excel, формирует payload и отправляет изменения в API.

## 6. Сборка

`build_main.bat` включает в PyInstaller-сборку только используемые каталоги:

```text
icon/
shared/
Adapters/
Sets/
Matrix/
Validator/
```

`importxml/` является отдельным инструментом и в основной EXE не включается.

Основные runtime-зависимости проверяются перед сборкой: `PySide6`, `pandas`, `requests`, `cryptography`, `openpyxl`.

Выходной файл:

```text
dist/Larix_Main.exe
```

## 7. Артефакты и локальные данные

Не должны коммититься:

| Путь/маска | Причина |
|---|---|
| `build/`, `dist/`, `*.spec` | Артефакты PyInstaller. |
| `__pycache__/`, `*.pyc` | Python-кэш. |
| `.venv/`, `venv/` | Локальные окружения. |
| `*.log`, `*.har` | Runtime/диагностические файлы. |
| `*.db`, `*.sqlite*` | Локальные БД. |
| `exports/`, `export/`, `Новая папка/` | Пользовательские выгрузки. |
| `.env*` | Локальная конфигурация/секреты. |
| рабочие файлы `importxml/*.{xlsx,xls,xml,...}` | Пользовательские входные/выходные данные. |

## 8. Хрупкие места

- `shared/app_common.py` использует динамическую загрузку модулей, а `main.py` хранит карту загружаемых классов. При переименовании классов или файлов нужно синхронно менять `MANAGER_MODULE_LOADERS`.
- `shared/theme_toggle.py` используется всеми основными GUI-модулями; изменения темы имеют широкий эффект.
- `Adapters/ui.py`, `Sets/ui.py`, `Matrix/ui.py` и `Validator/ui.py` крупные и совмещают UI с обработкой данных; изменения лучше делать локальными.
- Пути к изображениям используются во время runtime и PyInstaller-сборки. Перед удалением иконки нужно проверить ссылки на неё по всему проекту.

## 9. Правила изменений

1. Сначала определить минимальный набор затрагиваемых файлов.
2. Не менять форматы XML/Excel без отдельной задачи.
3. После изменения архитектуры обновлять этот документ.
4. Перед сборкой проверить синтаксис изменённых Python-файлов.
5. После изменения состава модулей синхронизировать `build_main.bat`, `requirements.txt`, README и этот файл.


## Excel-шаблоны и несколько листов

`shared/excel_template.py` формирует единый демонстрационный Excel-шаблон. В нём специально связаны примеры для всех основных разделов: `Набор 1`, `Набор 2`, `Наборы матрицы`, `Матрица 1`, `Матрица 2` и `Адаптер`.

- `Adapters/ui.py` умеет импортировать несколько Excel-листов и поддерживает несколько групп параметров в одном листе адаптера.
- `Sets/ui.py` выбирает один Excel-файл и несколько листов. Листы можно объединить в один Set-профиль или создать отдельный профиль для каждого листа.
- `Validator/ui.py` работает аналогично: несколько листов можно объединить в один профиль проверки параметров или оставить отдельными.
- `Matrix/ui.py` использует один Excel-файл одновременно для матричных листов и листа наборов. Можно отметить несколько матриц; они сохраняются как отдельные профили внутри одного `.cv`-файла.
- `shared/guide.py` добавляет в каждый основной раздел кнопку с `circle-info.png` и краткой инструкцией по текущему рабочему процессу.
